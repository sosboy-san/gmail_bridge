外部メールを、自分のGmailに集約

いつものメールを、
自分のGmailへ。

会社メールも、独自ドメインも、プロバイダーメールも。
Gmail以外のメールを、自分のGmailへ取り込むためのセルフホスト型Bridgeです。

取り込んだメールを、いつものフィルタ・ラベル・検索で整理。パソコンでもスマートフォンでも、同じGmailアカウントでまとめて扱えます。

NASやDockerなどを自分で運用できる方向けのツールです。利用者自身の環境とGoogleの認証情報を使って動かします。

できることを見る導入を検討する

こんな人向けです

  • 会社メールや独自ドメインのメールをGmailにまとめたい
  • 外部POP取得の終了後も、Gmailへの集約を続けたい
  • アプリに別アカウントを追加するだけでなく、自分のGmailへ取り込みたい
  • 外部メールでも、Gmailのフィルタやラベルを使いたい
  • Gmailの検索や、利用できるAI機能も活用したい
  • NAS・Linux・Dockerなど、自分で動かせる環境を持っている

Gmailを、これからもメールの集約先に

これまでGmailには、会社メールや独自ドメインなどの外部メールをPOPで取得し、自分のGmailに集める機能がありました。Googleがこの機能の終了を案内したことで、同じ使い方を続けるには別の方法が必要になります。

困るのは、メールを読む方法だけではありません。外部メールをGmail本体へ集約し、フィルタ・ラベル・検索などを一体として使う方法が失われることです。

Gmailアプリで「見る」から、
Gmailに「入れる」へ。

アプリに外部アカウントを追加

外部サーバーのメールをGmailアプリで閲覧します。それだけでは、自分のGmailアカウントにメールが保存されるわけではありません。

Gmail Bridgeで取り込む

外部メールを自分のGmailアカウントへ保存します。Gmailに届くほかのメールと一緒に、Web版でもモバイル版でも扱えます。

自動転送が使えれば集約できますが、メールサービスや会社の運用によっては転送できない場合もあります。転送は使えなくても、IMAPでメールを取得できる。そんな環境からも、これまでのようにGmailへ集約し続けたい。そのためにGmail Bridgeを作りました。

Googleの案内では、外部POP取得は既存ユーザーも2027年1月までの提供予定です（2026年9月確認）。最新の予定はGoogleの公式案内をご確認ください。

外部メールにも、Gmailの使いやすさを

Gmailの正式なAPIを使ってメールを取り込みます。外部サーバーのメールを別アカウントとして表示するだけでなく、Gmailに保存されたメールとして活用できます。

外部メールにも、Gmailのフィルタを

送信者・宛先・件名を条件に、取引先や受信アドレスごとのラベルへ振り分け。Gmail側に用意したルールを活用できます。

ラベルとアーカイブで整理

仕事別にラベルを付けたり、対応済みのメールをアーカイブしたり。外部メールも、いつもの整理の流れに組み込めます。

探す場所を、Gmailにまとめる

差出人やキーワードで検索。複数の宛先に届いたメールを、Gmail内でまとめて探せます。

パソコンでも、スマートフォンでも

Web版とモバイル版で、同じGmailアカウントのメールを確認。端末が変わっても整理した結果を共有できます。

Gmail側のAI・返信支援も

取り込んだメールは、Gmail内のメールを対象とする要約や返信支援などの対象にできます。利用できる機能は、契約・アカウント・言語・地域・設定によって異なります。

Gmailと連携するサービスへ

Gmailを参照する外部サービスやAIにも、対応範囲と許可した権限に応じてメールを活用できます。連携は利用者自身が別途設定・承認します。

メールが届くまで

  1. 外部メールサーバー
  2. Gmail Bridgeが取得
  3. 自分のGmailへ取り込み
  4. Gmailのフィルタ・ラベル・検索で整理
  5. 必要ならスマートフォンへ通知

元メールを取得しただけで既読にはしません。取り込み時点の既読・未読状態をGmailへ反映します。通知は任意で、ntfyを使います。

標準の取り込み対象はINBOX（受信トレイ）のみです。送信済みやサブフォルダをまとめて巡回するものではありません。取り込み前に別フォルダへ移動されたメールは対象外です。設定で別の1フォルダを指定することもできます。

取り込み後の操作を元サーバーへ反映する双方向同期ではありません。複数の外部アカウントを使う場合は、それぞれにBridgeの設定と保存先を用意します。

添付ファイルとDriveへの退避

Gmailの添付ファイル制限は、危険なファイルから利用者を守る重要なセキュリティ機能です。一方で、悪意のない業務資料でも、たとえばパスワード付きZIPの中に、さらにZIPなどの圧縮ファイルが入っている構造は拒否される場合があります。詳しくはGmailがブロックするファイルの公式説明をご覧ください。

メールサーバーごとに添付ファイルの受信方針は異なります。Gmail Bridgeが対象とするのは、元のメールサーバーの運用方針で、すでに受信・保存されているメールです。そのメールをGmailへ取り込む段階で添付が拒否されても、本文をGmailで確認し、添付へアクセスする手段を残せるように、Driveへの退避機能を設けています。

この機能を有効にすると、Gmailが添付を拒否した際にGoogle Driveへ添付を保存し、Gmailには本文とDriveリンクを含む軽量版メールを取り込みます。アプリはDriveの共有設定を一般公開へ変更しません。

元サーバーで受信済みであることやDriveへの保存は、ファイルの安全性を保証しません。添付を開く際は、送信元や内容を確認し、利用者・組織のセキュリティ方針に従ってください。

元メールは、すぐに削除しません

元サーバーのメールを削除する機能は、設定でON/OFFを選べます。有効にした場合も、Gmailへの取り込み完了後、設定した猶予期間と安全確認を経て削除します。

最初は削除を無効にして試してください。取り込み結果や添付ファイルを確認してから、自分の運用に合った保存期間を決められます。

自分の環境で、自分のために動かす

Gmail Bridgeは、利用者自身のNAS・Linux・Docker環境で動かすツールです。QNAP NAS / Container Stationでの運用実績があります。こちらでメールを預かったり、ログインするだけで利用できるサービスを提供したりするものではありません。

導入には、利用者自身のGoogle Cloudプロジェクト、OAuthクライアント、認証情報が必要です。認証や初期化を行い、保存先と定期実行の環境を設定します。

公開コードと個人用OAuthについて

このサイトで案内するOAuthアプリは、所有者本人の個人運用専用です。公開コードを使う方は、各自のGoogle Cloudプロジェクトと認証情報を用意してください。所有者のOAuth認証情報は配布しません。

About Gmail Bridge

Bring external mail into your own Gmail account, rather than only viewing a separate account in the Gmail app. This self-hosted tool imports IMAP mail using the Gmail API, with optional Google Drive attachment fallback and ntfy notifications. Run it on your own infrastructure with your own Google Cloud project and OAuth credentials. The owner's OAuth app is for personal use; this is not a hosted sign-in service.
