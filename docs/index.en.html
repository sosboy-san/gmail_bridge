Who is this for?

  • You want company or custom-domain mail in Gmail itself.
  • You need an alternative to Gmail's external POP fetching.
  • Adding a separate account to the Gmail app is not enough.
  • You want Gmail filters, labels, search and supported integrations.
  • You have a NAS, Linux or Docker environment you can manage.

Gmail integrations

Connect supported services separately with your own permission choices.

Bridge uses the official Gmail import API. Its read-state/label updates can affect the final result of some Gmail filters; test a few messages first. Bridge does not provide AI features or automatically send mail to external AI.

How mail arrives

  1. External IMAP server
  2. Bridge fetches mail
  3. Import into Gmail
  4. Organize in Gmail
  5. Optional ntfy notification

Fetching does not mark source mail read. Its read/unread state is reflected at import time, not continuously synchronized.

By default, only INBOX is imported. Configure another single mailbox if needed. Sent mail/subfolders are not recursively traversed; mail moved away before fetching is outside the selected mailbox.

This is one-way import. Give each source account its own configuration and state directory.

Attachments and Google Drive fallback

Gmail's attachment restrictions protect users, but can also reject legitimate business files, including some nested encrypted archives. See Google's blocked-file guidance.

Bridge handles messages already accepted and stored by the source server. If Gmail rejects their attachments, it stores attachments in your Drive and imports a reduced message containing the body and links. It does not make Drive sharing public.

Source acceptance or Drive storage does not establish file safety. Follow your organization's policy when opening attachments.

Source messages are not deleted immediately

Cleanup is optional and disabled by default. When enabled, it deletes only after import completion, a configured delay and safety checks. Start with deletion disabled and inspect the results before choosing retention.

Your infrastructure, your credentials

Run on your own NAS, Linux or Docker host. The owner has reported problem-free rc.2 operation on QNAP Container Station before v1.1.0 promotion. v1.1.1 adds IMAP timeout recovery.

This is not a hosted sign-in or mail-storage service. Provide your own Google Cloud project, desktop OAuth client and token. The owner's OAuth application is for the owner's personal deployment; its credentials are not distributed.

Get started with v1.1.1

First check the requirements and limitations. Pulling the image alone is not enough: configure IMAP and OAuth, mount persistent storage and explicitly initialize a new deployment.
