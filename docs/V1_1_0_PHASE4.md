## 設定と判定

`include_sender=false / include_subject=false / sender_filter_mode=off` を既定とします。送信元はFromから一意に正常解析できたアドレスだけを使い、表示名は含めません。件名はUTF-8ヘッダを復号します。表示値は改行・制御文字等を除去し、各200文字を上限に省略します。FromとSubjectは独立して扱い、不足した項目だけを省略します。フィルタ用のアドレスは表示時の省略前の値です。

| モード | 対象 |
| --- | --- |
| off | 送信元を判定できなくても通常通知可能 |
| allowlist | 許可したアドレス／ドメインに完全一致 |
| blocklist | 除外に一致しない、一意に判定できる送信元 |
| combined | 許可に一致し、除外に一致しない送信元 |

比較は大文字小文字を区別しません。combinedでは、個別アドレスの許可よりドメイン除外が優先します。allowlist/blocklistではそのモードのリストを使います。空allowはallowlist/combinedで通知なし、空blockはblocklistで判定可能な送信元を全件許可します。サブドメインを自動で含めず、正規表現・ワイルドカードも使用しません。

設定例は `notification_senders.example.ini` を追加しました。実際のリストINIはgitignore対象です。通知無効・フィルタoffならリストファイルを開きません。判定元はFromヘッダです。送信者の検証はメールサーバー側の運用も含めて行ってください。

## 記録と確定

Gmail API成功直後、Gmail IDと同じDB更新で、元メールから得たsender/subjectと専用UTC時刻を記録します。時刻・メタデータは最初の成功記録を保持し、ラベル処理や再開で上書きしません。通知表示・通知再送のためのIMAP再取得は行いません。従来のメール最終処理再開に必要なIMAP取得は引き続き行います。

通常importとDrive fallbackの最終状態確定・削除予約・通知登録を同じトランザクションへまとめ、二重の通知登録経路を削除しました。最終確定に失敗するとAPI成功待ち状態へ戻り、Gmail再importをせず最終処理から再開します。

## TTLと状態

`ttl_minutes` 未指定／0は無期限。新規設定例は15分。未指定時の情報ログはDBに記録して一度だけ表示します。

通知処理は、最新設定の検証、TTL確認、送信元判定、送信の順です。最新設定が不正なら状態を変更せず停止します。TTL境界は経過時間が設定分数以上になった時点です。TTLが有効で時刻不明ならexpired。旧DBの時刻はPhase 2の移行で引き継ぎます。

状態はpending → sent / suppressed / expired。sent・suppressed・expiredは再登録や失敗記録で復活させません。expiredは正常な終了状態で、メールの取り込み状態・削除予約には影響しません。

一度の機会で通信は最大10件／30秒を目安に制限し、送信失敗後はその機会で追加通信を止めます。ただし古い通知の期限切れ・対象外の抑止判定は続けます。単一HTTP要求は既存の15秒timeoutを使用するため、30秒は厳密な総実行時間上限ではありません。

大量取り込みでは5件ごと、または30秒経過後に通知機会を設け、最後にも残りを処理します。通知失敗後は取り込みループ内で30秒の通信再試行猶予を設け、各少量バッチでtimeoutを繰り返さないようにします。通知の全件処理完了を待つためにメール取り込みを停止しません。

## initと設定変更

initの選択UIDは、Gmail接続／取り込み前にinit由来として保存します。まだ処理していないUIDを含め、中断後のrun再開でも通常通知を生成しません。通常・Drive fallbackの両方に適用します。既に完了した通常取り込みの既存通知や、旧DBで由来が不明な通知は推測で抑止しません。

新しいメールを処理する前、および通知送信直前に設定を再読込します。既にAPI成功したメールは当該処理の設定で最終状態を保存し、その後に最新通知設定を判定します。接続先・ログイン・mailbox・OAuthファイルの設定が変わった場合は、旧接続を使い続けず `[CONFIG_RESTART_REQUIRED]` で次周期の接続へ引き継ぎます。設定／DB更新でinitは実行しません。

障害・復旧通知には通常メールの送信元フィルタ・表示項目・TTLを適用しません。有効設定と従来の障害状態管理に従います。実運用の障害・復旧送信経路でも送信前に最新設定を検証し、不正設定中は送信しません。
